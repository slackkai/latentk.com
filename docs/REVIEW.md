## 修复

- 配置迁移未完成造成 19 个类型错误：首页仍导入已删除的 `ArmHero`，工作台、研究方向、留言表单引用不存在的导出，板块副标题字段不一致。
- GitHub Pages 子路径下的导航、图片、RSS、canonical、favicon 与搜索资源丢失部署前缀。
- 资料库和项目显示标签链接，却没有生成相应标签页面；全站 RSS 也遗漏这两个板块。
- 特殊标签（如 `AI/ML`、`C#`）导致路由构建失败；标签现在生成跨平台安全的 URL。
- 主题开关未接入：首页板块、Now、目录、阅读进度、文章元信息、热力图、相关推荐、工作台和默认配色。
- ClientRouter 切页后搜索快捷键、配色、目录与阅读进度的全局事件监听没有解除。
- 搜索加载竞态、弹窗焦点约束、关闭后过期结果、重复的列表/标签搜索结果。
- Git 最后修改时间使用 shell 拼接文件名，改为独立参数调用。
- 日期按 UTC 处理，避免 CI 与本地时区导致纯日期偏移；热力图统计排除未来日期。
- 留言表单发件名称写死、空邮箱被替换为不合法邮箱文本、重复提交防护。
- 依赖升级至 Astro 7、兼容的 MDX 和 Markdown 处理器，保留 KaTeX 与代码高亮。

## 验证方法

- `npm run check`：Astro / TypeScript 检查。
- `npm test`：部署路径、Markdown 资源改写及 CMS 草稿默认值回归。
- `npm run test:production`：临时生产构建，验证草稿过滤、资料库标签、RSS、禁用板块与功能开关；测试后恢复源文件。该命令会覆盖 `dist`，完成后重新 `npm run build`。
- `npm run build && npm run verify`：生成静态页面与 Pagefind，检查站内链接、图片、脚本、锚点、CMS 配置和搜索产物。
- CI 同时覆盖域名根路径与 `/theme-test` 子路径。

浏览器验收覆盖首页、搜索结果跳转、公式/MDX 批注、资料库筛选、配色与移动菜单。CMS 使用官方 test-repo 虚拟仓库验证新建、保存、重新打开草稿；GitHub token 登录及真实内容提交由站长首次连接后完成。没有发送测试留言邮件。

## 已知边界

- 示例文章仅用于主题展示，使用前应替换，不代表作者的真实项目或发表经历。
- 界面语言与作者内容分开；默认提供中文、英文界面，文章及作者配置中的文字由作者维护。
- 热力图以最近一次构建日期为准，纯静态网站不会在午夜自行重新构建。
- MDX 构建可能出现上游 bundler 关于 `use astro:head-inject` 的提示，公式与页边批注页面仍经过构建和浏览器检查。
- 留言邮件需要自行配置 Web3Forms key。
