目标明明在这里，程序却把机械臂指向了另一边。

最省事的办法，是补一个偏移量：往左挪一点，再往前挪一点。眼前这个点对了，换一个位置，又偏了。

先别继续挪。这里有一份故障现场，三种看起来都说得通的解释，以及几项可以任选的检查。**这次不按作者的顺序读答案，由你决定先查哪里。**

:::postit[这是一份可重开的案卷]{info}
场景、坐标与故障均为教学构造。工作台不连接机器人，不执行真实运动。你可以改判断、试错、重新开卷；原始证据会保留到本次重置为止。
:::

## 现场只告诉了你这些

我们把相机坐标系叫 C，基座坐标系叫 B。一个点写在不同坐标系里，就像同一个地址可以从不同路口描述，数字会变，位置不应变。

这份案卷已经独立测好了几个对应关系：C 的原点在 B 中是 `(0.4, -0.2, 0.5)` 米；沿 C 的正 x 走，应当沿 B 的正 y 移动；沿 C 的正 y 走，应当沿 B 的负 x 移动。z 方向不变。

坐标都用米，都是列向量。现在，程序给出的目标点却不符合这份约定。

可能是旋转方向写反了，可能是平移多了十厘米，也可能是毫米没有换成米。你手里的第一步，不是一个补丁，而是一个选择：**哪项检查最有可能让这些解释分开？**

:::layout{wide}
::embed[坐标案卷：任选检查，保留证据，提出解释，再对独立夹具做修复后的回归。]{page=./attachments/workbench}
:::

如果你想自己查完再读解释，可以在这里多待一会儿。解开第一卷后，还有两个不同故障；不用换一套按钮，只要重新组织证据。

## 第一条线索：原点很省事，也很容易骗人

你可能先测了 C 的原点。很好算：那里没有离开原点的位移，转换后只剩平移量。

如果它都错了，平移值得怀疑；如果它对了，却不能说明旋转也对。旋转一个零向量，无论转对还是转反，仍然是零。

这就是为什么一个测试“通过”，有时几乎没有排除任何解释。它不是白做了，而是你要知道它检查到了哪一层。

再沿 x 或 y 走十厘米。现在，旋转终于有了可以作用的方向。你会看见几种原因留下不同的脚印：方向反了、整段挪开了，或尺度大得离谱。

**好测试不是越复杂越好，而是让不同解释给出不同答案。**

## 第二条线索：原路返回，不等于走对了路

工作台里还放了一项很让人放心的检查：把点从 C 送到 B，再送回 C。

它通过了。是不是可以排除坐标变换的问题？

先想一个更熟悉的场景：你把地图拿反了走出去，又按同一张反地图倒着走回来，仍然可能回到出发地。来回自洽，并不能证明中途到的是正确目的地。

这份案卷故意让正向和逆向函数成对地犯错。因此三种故障都能通过往返检查。你需要地图之外的路标，也就是那几组**独立已知的坐标对应**。

:::note[“预期答案”从哪里来，很重要]
如果用待测函数生成预期值，再用同一个函数验证，测试就容易变成“它与自己一致”。往返、不变量和独立夹具检查的不是同一件事，最好让它们互相补充。
:::

## 第三条线索：先解释所有证据，再动一个地方

在案卷一里，原点正确，非零方向却不对。最后的修复不是“再补十厘米”，而是改正旋转使用的方向。

一次补偿可以让某个点刚好对上，却未必能解释为什么别的点偏向另一边。工作台要求你先收集足以区分列出的三种解释的证据，再允许结案；即使一开始猜中了，也要补上这一环。

改完以后，它会检查原点、三个基向量和目标点，包括你刚才没有亲手测过的点。旧的错误记录不会被新结果覆盖，因为它们正是这次修改为什么必要的依据。

这套动作可以迁移到别的故障：**保留失败例子，做最小修改，再检查邻近但不相同的情况。** 不要同时改单位、标定矩阵和控制参数，否则“好了”以后仍然不知道是谁起作用。

## 把第一份案卷拆到公式里

到这里，再看矩阵就不那么像一堵墙了。约定是：

$$
p_B=R_{BC}p_C+t_{BC},\qquad
R_{BC}=\begin{bmatrix}0&-1&0\\1&0&0\\0&0&1\end{bmatrix},\quad
t_{BC}=\begin{bmatrix}0.4\\-0.2\\0.5\end{bmatrix}.
$$

$R_{BC}$ 把 C 中的方向写成 B 中的方向；$t_{BC}$ 再把原点移到相应位置。下标在不同库里可能另有约定，这里明确采用“输出 B、输入 C”。

目标点 $p_C=(0.1,0.2,1.0)^\top$ 先转成 $(-0.2,0.1,1.0)^\top$，再平移到 $(0.2,-0.1,1.5)^\top$。

如果误用 $R_{BC}^\top$，就会得到 $(0.6,-0.3,1.5)^\top$。这一次偏差是 $(0.4,-0.2,0)^\top$，但换一个输入点，偏差也会变。原因在于：

$$
\Delta p=(R_{BC}^\top-R_{BC})p_C.
$$

不是每个点都差同一截，当然不能靠一条固定偏移量修好。

:::fold[往返检查为什么仍会通过？]
正确的逆变换是 $p_C=R_{BC}^\top(p_B-t_{BC})$：先减平移，再旋转。

若错误正向用了 $R^\top p+t$，错误逆向恰好用了 $R(p-t)$，两处错误互相抵消：

$$
R\big((R^\top p+t)-t\big)=p.
$$

合法旋转也会保持点间距离。所以“距离没变”和“能回原点”都值得测，却都不单独保证方向使用正确。
:::

## 如果数值都对了，机械臂仍然抓偏呢？

那就不要为了把故事讲圆，宣布“问题已经解决”。

坐标变换只是链路的一站。深度单位、图像和姿态的时间同步、工具中心点、规划与执行，都可能继续产生偏差。下一步该查哪一环，取决于新的证据：目标数值是否正确？静止和运动时是否不同？规划目标与反馈位姿是否一致？

真实相机的光学坐标约定也不能直接套用这份构造矩阵。[ROS REP-103](https://www.ros.org/reps/rep-0103.html) 是核对单位与坐标约定的入口；进入硬件验证前，还需要平台自己的安全流程、限速与工作空间检查。

## 把这次推理装进文件，而不只记一句“修好了”

工作台结案后，可以保存一份诊断记录：你测过哪些点、看到什么、接受了哪个解释、改后验证到哪里。

没有开启交互，也可以下载 [frame_checks.py](./attachments/frame_checks.py)，用 Python 3.10+ 执行 `python frame_checks.py`。它只用标准库，会复算第一份案卷，并展示“错误正逆变换也能通过往返”的反例。

交互的三种故障和夹具则在 [model.js](./attachments/workbench/model.js)。所有预期点都来自本文明确写下的几何约定，不来自真实标定。

你最终带走的不必是这几个坐标。更值得带走的是那个停顿：下次手又要伸向“偏移量”时，先问问——**我现在缺的是一个补丁，还是一条能把原因分开的线索？**
